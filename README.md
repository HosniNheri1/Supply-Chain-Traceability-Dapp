# Supply-Chain Traceability DApp — Solidity + Hardhat + Sepolia + ethers.js — Ethereum Blockchain Project

**Authors:** Hosni Nheri & Oussema Mesfar
**Skills demonstrated:** Solidity smart-contract design (role-based access control, state machine, events), Hardhat testing and deployment (Mocha/Chai), Ethereum testnet deployment (Sepolia) and Etherscan verification, Web3 front-end integration (ethers.js v6 + MetaMask), wallet and RPC configuration (Alchemy), infrastructure troubleshooting

## Objective

Track a product from **manufacturing to delivery** with **timestamped, transparent checkpoints** stored on Ethereum. A smart contract enforces who may update a product and in which order, every checkpoint stores `block.timestamp`, and a web interface lets anyone read the full history while authorized actors write to it through MetaMask.

## Architecture

```
Web page (HTML + ethers.js v6)
        │
        ▼
MetaMask (signs transactions)
        │
        ▼
Alchemy RPC (gateway to Sepolia)
        │
        ▼
Ethereum Sepolia testnet (chain ID 11155111)
        │
        ▼
SupplyChain smart contract
(roles · stages · append-only history)
        │
        ▼
Etherscan (events, transactions, verified source)
```

| Component | Role | Details |
|---|---|---|
| `SupplyChain.sol` | Business logic | Solidity 0.8.24, OpenZeppelin `AccessControl`, 4-stage enum, custom errors |
| Hardhat | Dev toolchain | Compile, test, deploy, verify; local node on chain ID 31337 |
| `frontend/` | Web interface | `index.html` + `app.js`, ethers.js v6 `BrowserProvider` |
| MetaMask | Wallet | Holds accounts, signs every write transaction |
| Alchemy | RPC provider | HTTPS endpoint used by Hardhat to reach Sepolia |
| Etherscan (Sepolia) | Public proof | Verified code, Events tab, Read/Write Contract tabs |

## 2. The smart contract

| Function | Who | Effect |
|---|---|---|
| `createProduct(name, location)` | Manufacturer | Stage = Manufactured |
| `shipProduct(id, location, note)` | Manufacturer | Manufactured → Shipped |
| `updateTransit(id, location, note)` | Transporter | Shipped / InTransit → InTransit (repeatable) |
| `confirmDelivery(id, location, note)` | Retailer | InTransit → Delivered |
| `getProduct(id)` / `getHistory(id)` | Anyone | Read product and full checkpoint history |

Each stage change stores `block.timestamp`, the actor's address, a location and a note, and emits `ProductCreated` / `StageUpdated`. Skipped or repeated steps revert with the custom error `InvalidStage`; unknown IDs revert with `ProductNotFound`. The history is append-only: no function edits or deletes a past checkpoint.

## 3. Local tests (Hardhat)

```bash
npm install
npx hardhat compile
npx hardhat test                                          # 10 passing
npx hardhat node                                          # terminal 1: local chain
npx hardhat run scripts/deploy.js --network localhost     # terminal 2
npx http-server frontend -p 3000 -c-1                     # terminal 3: web page
```

In MetaMask, add the network `Hardhat Local` (RPC `http://127.0.0.1:8545`, chain ID `31337`, symbol `ETH`) and import the first private key printed by `npx hardhat node` (public test key, **local use only**).

> **⚠️ Gotcha — wrong folder.** `HHE3: No Hardhat config file found` came from running the command in the home directory. Fixed by running `cd supply-chain-dapp` first.

## 4. Deployment on Sepolia

1. Create an Alchemy app on **Ethereum Sepolia** and copy its HTTPS URL.
2. Use a **dedicated test wallet** in MetaMask and get Sepolia ETH from a faucet.
3. Create the secrets file (never committed):

```bash
cp .env.example .env        # Windows: copy .env.example .env
```

```
SEPOLIA_RPC_URL=https://eth-sepolia.g.alchemy.com/v2/<your-key>
PRIVATE_KEY=<dedicated test wallet, no real funds>
ETHERSCAN_API_KEY=<your-key>
```

4. Deploy and verify:

```bash
npx hardhat run scripts/deploy.js --network sepolia
npx hardhat verify --network sepolia <CONTRACT_ADDRESS>
```

The script prints the contract address and the Etherscan link, and writes the address into `frontend/contract-address.js`.

> **⚠️ Gotcha — faucets requiring mainnet funds.** The Alchemy, Chainlink and QuickNode faucets refused a brand-new wallet (they ask for mainnet ETH or LINK). Fixed by using the proof-of-work faucet (pk910): the browser mines for a few minutes, then the reward (0.066 SepETH) is claimed on-chain. Final balance: 0.068 ETH.

> **⚠️ Gotcha — VPN blocked.** The PoW faucet answered `IP Blocked` because a VPN used a hosting IP range. Fixed by turning the VPN off.

## 5. Using separate wallets for each role

```bash
# macOS / Linux
CONTRACT=0xYourContract MANUFACTURER=0xAAA TRANSPORTER=0xBBB RETAILER=0xCCC \
  npx hardhat run scripts/grantRoles.js --network sepolia
```

Windows PowerShell: set each variable first, e.g. `$env:CONTRACT="0x..."`. The admin can also grant roles from the "Admin" card in the web interface.

## 7. Troubleshooting log — real gotchas hit along the way

- **MetaMask not found**: the page was opened in a browser view without the extension. Fixed by opening `localhost:3000` in the normal browser window.
- **Sepolia not selectable**: MetaMask restricts networks per site. Fixed by switching from another tab, then adding Sepolia to the site's permissions.
- **`Cannot import invalid private key`**: the public address was pasted instead of the `Private Key:` line from `npx hardhat node`.
- **`missing revert data`**: the local node had been restarted, so the contract no longer existed. Fixed by clearing MetaMask activity data, redeploying and restarting the web server with `-c-1`.
- **Port 3000 already in use** (`EADDRINUSE`, 404 page): an older `http-server` was running from the wrong folder. Fixed by stopping it and restarting from the project folder.
- **Wrong currency symbol (`GO`)**: chain ID 31337 is also used by another network. Fixed by naming the network `Hardhat Local` with symbol `ETH`.
- **MetaMask internal error**: a UI crash unrelated to the code. Fixed by reopening MetaMask.
- **Credential hygiene**: the RPC URL contains an API key and must never be shared. If it is exposed, regenerate it in the Alchemy dashboard.
